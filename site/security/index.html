The security model

Vault Desk treats generated instructions as untrusted suggestions. The application — not the generated text — decides which approved action may run, checks its scope, and records the result. The ordinary interface never receives a general-purpose host shell or unrestricted file access.

Core protections

  • Read-only source folders. You choose the source folder. Vault Desk can inspect it but does not write changes back into it.
  • A separate work area. Generated files live in a bounded workspace, apart from the source material you selected.
  • Network isolation. Executable work runs inside a small virtual machine with no network interface.
  • Narrow local connections. Desktop components communicate through authenticated, current-user-only local channels.
  • Visible local evidence. Conversations, activity, generated files, and audit records remain available for local review.
  • No application telemetry. Vault Desk does not send analytics, crash reports, or background usage metrics.

Technical readers can inspect the full security architecture and supporting evidence in the public repository.

Release and platform status

Vault Desk has not published a supported desktop release. The macOS implementation has passed its current physical checks; Windows product integration and physical certification remain in progress. Download links will not be published until the required platform and packaging work is complete.

Report a vulnerability safely

Do not publish suspected vulnerabilities, sensitive reproduction details, customer data, credentials, or destructive examples in a public issue, discussion, pull request, or chat transcript.

Follow the repository's security policy for the current private-reporting instructions. If private reporting is not yet available, the policy explains how to request a private contact without disclosing the vulnerability publicly.
