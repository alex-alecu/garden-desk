## Change Brief

- Goal: let the local agent inspect selected folders and images, work iteratively in durable session workspaces, and run independent conversations concurrently inside a RAM-bounded pool of reusable offline microVMs.
- Authority: M3 was activated by the repository owner on 2026-07-20; the owner explicitly reopened ADR 0018 for the persistent-workspace revision on 2026-07-23.
- Product surface: New chat, immutable file attachments, direct or delegated PNG and JPEG inspection, folder groups, recent persistent sessions, drafts, durable messages, normalized execution records, durable inference traces, concurrent background conversations with sidebar activity, warm-session restoration, cancellation, in-run clarifying questions that replace the composer with a paged option picker, automatically discovered generated-file deliverables, Overview-first Technical details with a separate Steps tab, and the static public launch website with its synthetic interactive demo.
- Security boundary: the webview has no host authority; Vault Core owns grants, policy, audit, inference mediation, VM lifecycle, and workspace manifests; the guest has zero NICs, an immutable root, a live read-only `/source`, and writable access only to bounded `/workspace` and ephemeral `/run/user`.
- Platform scope: certified macOS VirtioFS and Windows HCS Plan9 with host and guest read-only enforcement.
- Explicitly deferred: host shell, writable source mounts, networking, package installation, Git tooling, in-app document renderers or editors, OCR/retrieval document intelligence, clinical decision support, external integrations, and arbitrary downloadable libraries.

### Current v13 agent behavior

- Core owns a persistent chat history and repeats model turn, tool calls, tool results, and model turn until the model returns text without calls. The worker uses Gemma's native function-call representation and returns every emitted call; malformed Python, Node, or shell source executes in the no-NIC guest and its real interpreter error becomes the next tool result. The only pre-execution loop guard blocks the third byte-identical call and tells the model to change approach.
- Core adds one fresh host-clock snapshot to the effective system prompt before every chat, retry, compaction, and child-agent model request. The snapshot contains the local ISO 8601 date and time with millisecond precision, UTC offset, and IANA time-zone name plus the matching UTC value. Zoned values compare as exact instants; date-only values compare with the local calendar date, and the same date is today. The snapshot is part of the traced effective prompt but not durable conversation history. It uses the operating-system clock and time-zone settings without network time access.
- The primary Markdown agent permits `bash`, `python`, `node`, `read`, `glob`, `grep`, `list`, `image`, `skill`, `task`, and `question`, with a 40-turn ceiling and 24 guest executions. Read/search tools execute inside the same guest roots. The question tool consumes no guest-execution budget and is unavailable to sub-agents. The primary run uses `image` for an ordinary question about one direct image. It delegates exact extraction and multi-image work to one general child, which returns only the required facts.
- Core accepts image paths only from exact immutable attachment names or below the active folder grant. It rejects final image links, escaping links, path escape, changed files, unsupported bytes, files above 32 MiB, edges above 8,192 pixels, and images above 40 megapixels. It gives the vision process one private PNG or JPEG snapshot, the approved model pair, and one bounded prompt. The process has no network access. Image inspection waits for active chat turns, unloads the resident chat worker, runs exclusively within the same memory budget, and removes all staged inputs afterward.
- A primary-agent question keeps the run, capacity lease, and session guest live while an in-memory request blocks the model turn. The desktop answers or dismisses it through typed RPCs; Stop aborts the pending promise, and Core restart retains the existing interrupted-run recovery behavior. Shared contracts retain the canonical nested 1-3 question schema, while the pinned Gemma adapter receives that array as one flat JSON string and Core parses and validates it before publication. If Gemma appends its tool-close transition after one complete question array, Core removes only that exact suffix before validation and before the next model turn. Protocol transitions inside question data and all transitions in other tool arguments remain invalid. This model-facing compatibility boundary was selected after physical stress runs showed nested tool schemas and leaked control text corrupting valid calls; the application contract was not weakened.
- The generic `read` tool accepts only UTF-8 plain text and rejects invalid UTF-8 or a NUL byte with `read_requires_utf8_text`. Tool output is limited to 2,000 lines or 50 KiB in model context, with the complete output spilled under `/workspace/.vault-output` and a `grep`/`read` retrieval hint. Generic prompt guidance tells the agent to inspect only small facts from a spill and to create a normal verified `/workspace` deliverable when the user needs the complete large result.
- `task` creates a persisted child run in the same session and warm VM. `explore` is read-only, `probe` can execute one focused trial, and `general` can complete one independent multi-step work unit. Children cannot call `task` or `question`, and only their final `<task_result>` enters the parent history. The primary agent must verify a child output before final use. Tool and sub-agent events appear as activity steps; paired sub-agent events collapse to one parent step.
- One complete agent run can retry one failed model call only for `internal`, `worker_crash`, or `malformed_worker_message`. A cold first-turn retry repeats the unchanged conversation with a new request identity; established history compacts before retry. Cancellation, timeout, memory, missing-model, unsupported, and request failures stop immediately. This model-call budget is separate from the one empty-answer retry and never replays a tool call.
- A cold run requests automatic context rather than substituting the 8K floor before the worker has measured this hardware. The request shape stays `auto` for the resident context while Core budgets from the returned allocation. Chat output uses up to 16,384 tokens while reserving at least 4,096 tokens for the prompt; compact summaries stay bounded at 2,048. An explicit question-tool test makes the first turn one question call without a planning turn. Measured prompt usage triggers anchored compaction at 80 percent of that allocation. Output exhaustion by itself does not compact history or remove typed tools: Core discards the failed turn, requests one immediate tool call or concise answer, and returns `agent_generation_limit` if the retry also exhausts its output. The summary follows Objective, Facts, Work State, Next Move, and Relevant Files and retains the current user request plus the last two assistant/tool turns verbatim. Three consecutive failed tools roll live history back to the last checkpointed working step and keep one short deterministic failure note with the last evidence, requesting a materially different approach. Follow-up runs receive the session's recent successful `/workspace` script paths so new requests extend saved programs instead of retyping their data. Durable conversation messages, execution records, traces, and audit records remain unchanged by context replacement.
- Session-summary refresh waits for a measured allocation of at least 16,384 tokens and skips while allocation remains `auto`. One summary inference can retry only `internal`, `worker_crash`, or `malformed_worker_message`; each attempt has a fresh identity and compaction trace turn. Cancellation, timeout, memory, unsupported, request, and repeated failures store no summary and do not change the completed run.
- Agent and skill specialization lives under `prompts/agents/*.md`, `prompts/system/*.md`, and minimal `prompts/skills/*/SKILL.md`. Agent frontmatter defines mode, literal tools, temperature, and steps; Core contains no document-format names, professional review policy, or keyword router. The XLSX skill teaches `openpyxl`, `reset_dimensions()`, first-row inspection, semantic header mapping, and exit-status-based warning handling. Professional review methods stay in their on-demand skill bodies.
- Desktop packaging reads the canonical generated Gemma 4 12B model and its projector directly instead of retaining copies under `src-tauri/resources`. The package also contains the allowlisted files from the hash-pinned llama.cpp b9842 image runtime and its MIT license. The Windows archive supplies its Microsoft OpenMP runtime, and the package adds only the three Visual C++ DLLs that its imports require from the pinned official x64 desktop runtime package. The resource manifest records the model pair at their final package paths and hashes every runtime file. macOS Tauri resources and Windows portable staging materialize model assets only in the completed application. Successful builds verify the packaged and canonical hashes before deleting profile intermediates, the prior package, and legacy staged copies. A failed or invalid replacement restores the prior same-profile package. Development removes transient model outputs when the process exits or when the explicit cleanup command runs. Verification does not remove a live development target model.
- Each active session starts or reuses one warm no-NIC VM, and one execution runs at a time within that conversation. Core maintains a least-recently-used pool bounded by the RAM remaining after the inference budget and host reserve: 1 VM on 16 and 24 GiB Macs, 2 on 32 GiB, and 5 on 48 GiB. Windows dedicated GPUs use a separate 2 GiB native-inference host reservation instead of subtracting discrete GPU VRAM. Windows integrated GPUs reserve the complete 8, 12, or 16 GiB inference budget from the shared host pool. Different conversations may overlap up to that capacity; excess runs queue, a second run in the same conversation is rejected, and idle sessions are evicted before busy sessions. Folder revocation retains the durable workspace, while session deletion removes it.
- Concurrent model turns run on one resident Gemma worker that loads the model once and exposes multiple parallel context sequences, so several turns can generate concurrently (bounded by a memory-derived sequence count, with user turns prioritized over sub-agent turns) without multiplying the model allocation; turns beyond the available sequence slots queue. The multi-sequence capability is verified from the shipped node-llama-cpp API; measured per-sequence memory, throughput effects, and Windows behavior remain unverified until the physical gate produces measurements and are never inferred from macOS. A queued turn remains cancellable, and its inference timeout begins only when worker execution starts. Generation receives at least five minutes and scales to 60 milliseconds per requested output token, allowing about 32 minutes 46 seconds for the 32,768-token maximum; probe and embedding operations retain five minutes.
- Automatic generation retains the 8K floor but does not expose Gemma's 256K trained maximum. On Windows, the signed helper reports DXCore adapter facts and installed RAM. TypeScript maps and isolates runtime devices, selects one usable dedicated GPU before one integrated GPU, and never uses vendor or speed as a support rule. A dedicated GPU needs at least 8 GiB and uses its complete isolated memory. Installed RAM sets an integrated maximum of 8 GiB at exactly 16 GiB, 12 GiB above 16 GiB through 24 GiB, and 16 GiB above 24 GiB. The isolated runtime capacity selects that tier or the next lower fixed tier. Less than 16 GiB installed RAM or less than 8 GiB isolated capacity is unsupported. Shared-memory profiles use combined CPU and GPU fitting, with 64K through 32 GiB installed RAM and 128K above. Dedicated profiles use device-memory fitting, with 64K through 24 GiB and 128K above. The runtime must see exactly the selected device at each model launch. Missing, ambiguous, changed, or aggregate device identity is unsupported.
- macOS passes the exact canonical folder path to one read-only VirtioFS share mounted at `/source`. Vault Core does not enumerate, flatten, stage, copy, or impose count or size limits on folder contents. Live mounting trades snapshot reproducibility for visibility of host changes.
- `/workspace` is a 128 MiB writable tmpfs. After each responsive execution, Core serializes shared-store mutation and atomically commits regular files and directories through a content-addressed manifest before content-addressed garbage collection. It rehydrates that manifest after VM, application, or machine restart. Traversal, devices, sockets, escaping links, hash mismatches, and blob replacement are rejected.
- The version-3 agent guest protocol adds execution identity, ordered bounded stdout/stderr frames, process lifecycle diagnostics, and final-result completeness validation to hello/capabilities, hydration, repeated execution, cancellation, workspace deltas, results, and graceful shutdown. The M1 probe remains version 1. Executed children retain the existing privilege and resource boundaries.
