# Milestone M3 Status

Updated: 2026-07-29

The persistent-workspace M3 implementation and canonical headless gate are certified on physical Apple silicon and Windows x64. The cross-platform M3 and Community Desktop V1 launch gate remain open for the remaining installed-Windows UI and debug-snapshot observations plus release-credential signing.

## Change Brief

- Goal: let the local agent inspect selected folders live, work iteratively in durable session workspaces, and run independent conversations concurrently inside a RAM-bounded pool of reusable offline microVMs.
- Authority: M3 was activated by the repository owner on 2026-07-20; the owner explicitly reopened ADR 0018 for the persistent-workspace revision on 2026-07-23.
- Product surface: New chat, immutable file attachments, folder groups, recent persistent sessions, drafts, durable messages, normalized execution records, durable inference traces, concurrent background conversations with sidebar activity, warm-session restoration, cancellation, artifacts, Overview-first Technical details with live logs, and the static public launch website with its synthetic interactive demo.
- Security boundary: the webview has no host authority; Vault Core owns grants, policy, audit, inference mediation, VM lifecycle, and workspace manifests; the guest has zero NICs, an immutable root, a live read-only `/source`, and writable access only to bounded `/workspace` and ephemeral `/run/user`.
- Platform scope: certified macOS VirtioFS and Windows HCS Plan9 with host and guest read-only enforcement.
- Explicitly deferred: host shell, writable source mounts, networking, package installation, Git tooling, document intelligence, external integrations, and arbitrary downloadable libraries.

## Implemented Mac Product

- The Tauri and React desktop retains native folder and file selection, grouped sessions, newest-five pagination, drafts, conversation restoration, task activity, generated files, cancellation, keyboard and responsive behavior. Its website-aligned visual system provides a continuous `#F5F4EB` warm-paper Light appearance and a neutral graphite Dark appearance with soft ivory type, satin depth, restrained jade actions, ember warnings, and visible keyboard focus. The full-height navigation divider resizes the left sidebar with pointer or keyboard input. A compact header control between Unload and Technical details cycles System, Light, and Dark; System follows live operating-system changes, explicit modes override them, and reload resets to System without browser storage. Active sidebar rows use a softly raised selection pill without an edge rule. Self-hosted OFL-1.1 IBM Plex typography remains pinned and bundled locally with its license; neither the desktop nor the public site contacts a font service. All assistant responses render as safe GFM, including single-line answers, tables, task lists, and strikethrough, within a wider unified chat layout; right-aligned user messages and assistant messages shrink to their content up to the conversation width, while HTML, images, and links remain inactive. The wider, application-colored Technical details drawer reduces the chat workspace instead of covering it. It opens to Overview without log bodies, shows memory allocation, budget, context, the current session ID, a wrapping local catalog path, and installed-app controls to create and reveal a private AI-agent debugging snapshot with SQLite-backed session records and bounded microVM logs; Logs contains collapsed execution rows with selectable Output, Errors, and typed VM diagnostics, explicit byte/truncation status, near-bottom following, and Jump to latest. The response metrics show prompt processing, generation speed, then total time. The webview supplies only the session ID and receives no filesystem or process authority.
- Files and folders can be dropped anywhere in the application window. A full-window animated affordance reflects native file, folder, or mixed-path classification before release; files attach to the active composer, folders become scoped workspaces, and the last dropped folder opens in a new blank conversation. Folder groups have persistent drag-handle and keyboard ordering. Pending attachments are clickable and removable; submission clears them from the composer and shows clickable immutable attachment chips beneath the durable user message.
- Vault Core persists schema-versioned state at catalog version 9. The v7 normalized execution records retain identity, source or command, state, bounded result evidence, truncation flags, and timestamps. Version 8 adds per-run inference turns whose exact effective prompts and canonical structured JSON payloads live in the immutable content-addressed store; version 9 adds persistent owner-defined folder ordering. New runs use trace version 1, schema-v7 history reports `not_recorded`, capture failures stop the loop, and restart recovery marks unfinished turns `interrupted`.
- The read-only `agent.trace` method resolves ordered trace payloads for explicit local diagnostics. Normal `agent.get` polling remains unchanged, and hidden model thought segments remain transient.
- Events, executions, messages, and audit metadata do not duplicate trace payloads; trace audit entries contain identifiers, hashes, outcomes, and execution links only.
- The packaged `vault-core debug-session` process mode opens catalog v9 read-only while the desktop remains running, isolates the selected session, verifies stored artifact and workspace hashes, retries a changing workspace manifest, and emits a fresh owner-only temporary snapshot with conversations, a host-safe mapping that preserves exact guest paths, generated artifacts, bounded execution evidence, and recorded or historical `not_recorded` traces. The desktop derives the catalog, bounds and validates helper output, remembers only the latest path per session for reveal, and exposes only safe diagnostic codes on failure.
- The Core-owned loop supports distinct Python and Node source actions plus shell command actions. It assigns `steps/NNNN.py` or `steps/NNNN.mjs` when needed, requires ESM imports for Node, records the assigned path before execution, preserves failed repair chains, and uses the actual allocated context or the certified 8K minimum. The structured grammar accepts one complete shell command without a grammar-level string cutoff, while Core requires the command to stay below 4,096 characters before execution; boundary-length commands, shell proposals that embed Python or Node source, and source containing model-protocol fragments are rejected before reaching the VM, and an unterminated quoted-string failure forces the next action into Python or Node source mode. A transaction, salary, advance, workbook, or spreadsheet task that discovers an `.xlsx` path case-insensitively in a recorded command, source, or stdout observation enters the source-only verified XLSX workflow on its next turn and counts XLSX coverage independently of other formats. A session whose first turn carries attached PDFs is forced into one Python source action so the files are read rather than guessed, unless earlier successful executions in the same session already read every exact attachment path; a follow-up may then answer from durable history instead of extracting the files again. A new executable proposal may generate up to 32,768 tokens, failed or rejected repairs and XLSX repair or continuation turns use 8,192, and forced final responses use 4,096; context assembly keeps at least 4,096 tokens for the current prompt, so the 8K context minimum reserves 4,096 output tokens. All observed stdout and stderr streams together use at most half the remaining prompt space, capped at 32,000 characters, with each oversized stream keeping its head and tail around a notice that names the excerpt; durable execution evidence keeps the complete streams. It returns `agent_context_exhausted` rather than dropping mandatory repair context. If generation reaches its limit, the loop records that failed trace turn and makes one explicit 8,192-token retry with new request identity, a 64-line source-only schema, and instructions to create or patch one small persistent workspace-file section before continuing in later turns; repeated exhaustion returns `agent_generation_limit` without executing partial output. When Gemma omits the function call but returns bounded plain text and the active schema permits a response, the worker converts only that text to the typed response action; execution-only schemas never accept this fallback. An otherwise missing structured call is recorded as a failed turn and gets one explicit structured-call retry that rebuilds the prompt against a 16,384-token context, so oversized observations shrink instead of being resent verbatim; the retry keeps the response-permitting schema so the bounded plain-text fallback stays reachable, carries exactly one function-call instruction as its final line, and is traced as its own turn, so the loop never hides an internal prompt inside the original trace.
- Each active session starts or reuses one warm no-NIC VM, and one execution runs at a time within that conversation. Core maintains a least-recently-used pool bounded by the RAM remaining after the inference budget and host reserve: 1 VM on 16 and 24 GiB Macs, 2 on 32 GiB, and 5 on 48 GiB. Windows derives the same pool from host RAM with a separate 2 GiB native-inference reservation instead of subtracting discrete GPU VRAM. Different conversations may overlap up to that capacity; excess runs queue, a second run in the same conversation is rejected, and idle sessions are evicted before busy sessions. Folder revocation retains the durable workspace, while session deletion removes it.
- Concurrent model turns queue through one serialized resident Gemma worker, so parallel guests never multiply the model allocation. A queued turn remains cancellable, and its inference timeout begins only when worker execution starts. Generation receives at least five minutes and scales to 60 milliseconds per requested output token, allowing about 32 minutes 46 seconds for the 32,768-token maximum; probe and embedding operations retain five minutes.
- macOS passes the exact canonical folder path to one read-only VirtioFS share mounted at `/source`. Vault Core does not enumerate, flatten, stage, copy, or impose count or size limits on folder contents. Live mounting trades snapshot reproducibility for visibility of host changes.
- `/workspace` is a 128 MiB writable tmpfs. After each responsive execution, Core serializes shared-store mutation and atomically commits regular files and directories through a content-addressed manifest before content-addressed garbage collection. It rehydrates that manifest after VM, application, or machine restart. Traversal, devices, sockets, escaping links, hash mismatches, and blob replacement are rejected.
- The version-3 agent guest protocol adds execution identity, ordered bounded stdout/stderr frames, process lifecycle diagnostics, and final-result completeness validation to hello/capabilities, hydration, repeated execution, cancellation, workspace deltas, results, and graceful shutdown. The M1 probe remains version 1. Executed children retain the existing privilege and resource boundaries.
- The reproducible guest contains Linux 6.18.7, BusyBox 1.38.0, Python 3.14.5, Node.js 24.18.0, Pillow 12.0.0, pypdf 6.14.2, openpyxl 3.1.5, et-xmlfile 2.0.0, defusedxml 0.7.1, lxml 6.0.2, typing-extensions 4.15.0, and python-docx 1.2.0. It exposes all 292 installed executable paths, including `/bin/sh`, `find`, `grep`, `sed`, `awk`, `diff`, `patch`, and `tar`, while omitting pip, npm, package managers, Git, compilers, and Python `ensurepip` payloads.
