# Milestone M3 Status

Updated: 2026-08-04

The persistent-workspace M3 implementation and canonical headless gate are certified on physical Apple silicon and Windows x64. The cross-platform M3 and Community Desktop V1 launch gate remain open for the named installed-Windows debug-snapshot, live-execution, standard-user setup, macOS lower-tier context observation, and release-credential signing.

## Change Brief

- Goal: let the local agent inspect selected folders live, work iteratively in durable session workspaces, and run independent conversations concurrently inside a RAM-bounded pool of reusable offline microVMs.
- Authority: M3 was activated by the repository owner on 2026-07-20; the owner explicitly reopened ADR 0018 for the persistent-workspace revision on 2026-07-23.
- Product surface: New chat, immutable file attachments, folder groups, recent persistent sessions, drafts, durable messages, normalized execution records, durable inference traces, concurrent background conversations with sidebar activity, warm-session restoration, cancellation, artifacts, Overview-first Technical details with a separate Steps tab, and the static public launch website with its synthetic interactive demo.
- Security boundary: the webview has no host authority; Vault Core owns grants, policy, audit, inference mediation, VM lifecycle, and workspace manifests; the guest has zero NICs, an immutable root, a live read-only `/source`, and writable access only to bounded `/workspace` and ephemeral `/run/user`.
- Platform scope: certified macOS VirtioFS and Windows HCS Plan9 with host and guest read-only enforcement.
- Explicitly deferred: host shell, writable source mounts, networking, package installation, Git tooling, document intelligence, external integrations, and arbitrary downloadable libraries.

The structured grammar accepts one complete shell command without a grammar-level string cutoff, while Core requires the command to stay below 4,096 characters before execution; boundary-length commands, shell proposals that embed Python or Node source, and source containing model-protocol fragments are rejected before reaching the VM, and an unterminated quoted-string failure forces the next action into Python or Node source mode. A transaction, salary, advance, workbook, or spreadsheet task that discovers an `.xlsx` path case-insensitively in a recorded command, source, or stdout observation enters the source-only verified XLSX workflow on its next turn and counts XLSX coverage independently of other formats. A session whose first turn carries attached PDFs is forced into one Python source action so the files are read rather than guessed, unless earlier successful executions in the same session already read every exact attachment path; a follow-up may then answer from durable history instead of extracting the files again. A new executable proposal may generate up to 32,768 tokens, failed or rejected repairs and XLSX repair or continuation turns use 8,192, and forced final responses use 4,096; context assembly keeps at least 4,096 tokens for the current prompt, so the 8K context minimum reserves 4,096 output tokens. All observed stdout and stderr streams together use at most half the remaining prompt space, capped at 32,000 characters, with each oversized stream keeping its head and tail around a notice that names the excerpt; durable execution evidence keeps the complete streams. It returns `agent_context_exhausted` rather than dropping mandatory repair context. If generation reaches its limit, the loop records that failed trace turn and makes one explicit 8,192-token retry with new request identity, a 64-line source-only schema, and instructions to create or patch one small persistent workspace-file section before continuing in later turns; repeated exhaustion returns `agent_generation_limit` without executing partial output. When Gemma omits the function call but returns bounded plain text and the active schema permits a response, the worker converts only that text to the typed response action; execution-only schemas never accept this fallback. An otherwise missing structured call is recorded as a failed turn and gets one explicit structured-call retry that rebuilds the prompt against a 16,384-token context, so oversized observations shrink instead of being resent verbatim; the retry keeps the response-permitting schema so the bounded plain-text fallback stays reachable, carries exactly one function-call instruction as its final line, and is traced as its own turn, so the loop never hides an internal prompt inside the original trace.
- Authored model instructions now have one source of truth under root `prompts/`: system, conditional state, recovery, and protocol Markdown plus progressively disclosed `SKILL.md` packages for terminal commands, attached PDFs, and XLSX workbooks. Skill folders validate the open Agent Skills name and description contract; Core selects relevant bodies from the user task, attachment names, and explicit typed workflow state without command-specific parsers. The terminal body is selected by matching task evidence instead of being globally active; direct-answer and format-specific tasks omit it unless their trusted inputs also call for shell work. Arbitrary file contents and model output cannot select instructions. The generic terminal workflow requires every executable, option, pipeline stage, and operand to be complete, treats empty output as no candidate rather than an inferred path, and directs fragile multi-stage searches to Python or Node source. Prompt growth is included in the observation budget at the certified 8K minimum. Desktop packaging copies the full tree, records every prompt hash, and the Windows host verifies and read-locks every packaged prompt before Core starts.
- Desktop packaging reads the canonical generated Gemma 4 12B file directly instead of retaining another model under `src-tauri/resources`. The resource manifest records that external input at its final package path, macOS Tauri resources and Windows portable staging each materialize it only in the completed application, and successful builds verify the packaged and canonical hashes before deleting profile intermediates, the prior package, and any legacy staged copy. A failed or invalid replacement restores the prior same-profile package. Development removes its transient model output when the process exits.
- Each active session starts or reuses one warm no-NIC VM, and one execution runs at a time within that conversation. Core maintains a least-recently-used pool bounded by the RAM remaining after the inference budget and host reserve: 1 VM on 16 and 24 GiB Macs, 2 on 32 GiB, and 5 on 48 GiB. Windows derives the same pool from host RAM with a separate 2 GiB native-inference reservation instead of subtracting discrete GPU VRAM. Different conversations may overlap up to that capacity; excess runs queue, a second run in the same conversation is rejected, and idle sessions are evicted before busy sessions. Folder revocation retains the durable workspace, while session deletion removes it.
- Concurrent model turns queue through one serialized resident Gemma worker, so parallel guests never multiply the model allocation. A queued turn remains cancellable, and its inference timeout begins only when worker execution starts. Generation receives at least five minutes and scales to 60 milliseconds per requested output token, allowing about 32 minutes 46 seconds for the 32,768-token maximum; probe and embedding operations retain five minutes.
- Automatic generation retains the 8K floor but no longer exposes Gemma's 256K trained maximum. Macs through 32 GB unified memory and Windows GPUs through 24 GB dedicated VRAM are capped at 64K; Macs and Windows GPUs above those respective thresholds are capped at 128K. Windows accepts only one non-unified runtime device's dedicated capacity and rejects multi-device aggregates or readings that include unified or shared system memory. Existing memory fitting can select a smaller context. The higher Mac threshold preserves its shared memory pool for the operating system, desktop, and agent guests.
- macOS passes the exact canonical folder path to one read-only VirtioFS share mounted at `/source`. Vault Core does not enumerate, flatten, stage, copy, or impose count or size limits on folder contents. Live mounting trades snapshot reproducibility for visibility of host changes.
- `/workspace` is a 128 MiB writable tmpfs. After each responsive execution, Core serializes shared-store mutation and atomically commits regular files and directories through a content-addressed manifest before content-addressed garbage collection. It rehydrates that manifest after VM, application, or machine restart. Traversal, devices, sockets, escaping links, hash mismatches, and blob replacement are rejected.
- The version-3 agent guest protocol adds execution identity, ordered bounded stdout/stderr frames, process lifecycle diagnostics, and final-result completeness validation to hello/capabilities, hydration, repeated execution, cancellation, workspace deltas, results, and graceful shutdown. The M1 probe remains version 1. Executed children retain the existing privilege and resource boundaries.
